⏺ The math is now concrete. Here's my diagnosis.

  TL;DR

  The belief tasks fail because of a chicken-and-egg at the heart of the
  wake-sleep loop: the default phase-1 corpus contains no belief task shallow 
  enough to solve from raw primitives, so no solved program ever contains the
  fork∧sync compound, so stitch never invents the agent constructor, so witness
  and dual belief stay permanently out of enumeration reach. Three secondary
  dynamics (the stall-break, the dreamed Q, and DSL cost inflation) then make
  sure the loop gives up before anything can change.

  The numbers

  I computed the description-length cost of each family's ground-truth program
  under the exact content_q the searcher uses (probe script, cube DSL, phase 1):

  ┌───────────────────────────────────┬───────┬─────────────┬───────────────┐
  │              family               │ nodes │ cost (nats) │ budget window │
  ├───────────────────────────────────┼───────┼─────────────┼───────────────┤
  │ plain wall belief (scaffold only) │ 11    │ 13.9        │ 6             │
  ├───────────────────────────────────┼───────┼─────────────┼───────────────┤
  │ goal-displacement                 │ 11    │ 12.1        │ 6             │
  ├───────────────────────────────────┼───────┼─────────────┼───────────────┤
  │ witness belief                    │ 16    │ 18.5        │ 9             │
  ├───────────────────────────────────┼───────┼─────────────┼───────────────┤
  │ dual belief                       │ 23    │ 29.7        │ 14            │
  └───────────────────────────────────┴───────┴─────────────┴───────────────┘

  Enumeration walks 2-nat windows, and each window holds roughly e²≈7.4× more
  programs than the last. So from raw primitives, witness belief is ~e^4.6 ≈
  100× more search than plain belief, and dual is ~e^16 ≈ 10⁷×. No value of
  --t-fn buys that. On top of the window depth, witness/dual scenes have 4 
  visible cell values (all boosted to cost 0 by content_q), so every program
  skeleton with k cellvalue slots gets 4^k same-cost fillings instead of 2^k —
  each window is also ~50–100× slower to sweep than on two-entity scenes.

  Why the abstraction ladder never fires

  The design (per the code comments) is: obstacle donates the policy, plain
  belief solves cheaply, stitch abstracts fork(policy, sync), and then witness =
  compose(<constructor>, seek) ≈ 10.5 nats (window 5) and dual ≈ 13 nats
  (window 6) — both easily reachable. That ladder is sound. But:

  1. The rung it stands on isn't in the corpus. In run_phase, use_witness = cube
  and not plain_belief, and cube is hardcoded True — so the plain single-agent
  belief tasks (the only fork∧sync compound solvable from scratch, window 6) are
  replaced by witness tasks. The scaffold that fixes exactly this exists
  (--curriculum, experiment.py:675) but is off by default. Your instrumentation
  line will be printing agency constructor in D: ABSENT every round.
  2. Goal-displacement alone can't seed the constructor. Even when
  goal-displacement solves (it's window 6), all 24 of its solutions share the
  step-derive, so stitch's MDL-optimal abstraction bakes step into the body
  rather than leaving an fn-typed derive hole (a hole costs one token per use
  and saves nothing when every use is step). Witness needs the wall-derive form.
  Only when wall-belief and step-belief solutions coexist in one stitch pool
  does antiunification produce fork(compose($f, optimize(neg_dist $gv) $av), 
  sync_to_world $av) — the constructor with the derive hole.
  3. The stall-break kills the run before the fallback rounds.
  experiment.py:854: if n_solved == n_before and it > 1: break. Round 1 solves
  the shallow families; if round 2 adds nothing, the loop exits — it never
  reaches round 4, which is the first round that reverts to the uniform/content
  Q (use_model is on for rounds 2–3). The mop-up round the comments promise ("a
  model that mis-prioritises belief can never make it unreachable") is
  unreachable in exactly the stalled case it was designed for.
  4. The dreamed Q makes rounds 2–3 worse for belief, despite the uniform floor.
  dreamed_q takes max(model, uniform), which is unnormalized (probabilities sum
  > 1). It never raises the target's cost, but it drops the cost of everything
  the model likes toward 0 — and the model is trained only on replays from the
  solved families, which contain no fork/sync. Under a fixed timeout, flooding
  the early windows with cheap non-belief programs means fewer windows get
  swept. "Can only help" is true window-wise but false time-wise, and rounds 2–3
  are precisely when witness would first become reachable after a stitch. Two
  aggravators: MatRecognitionModel's role-by-motion encoding pools both movers
  into h_agent0 (witness/dual scenes are outside its representable space), and
  dream's fantasy grids use hardcoded _av_list=[1] plus all corpus goal values
  (~7 entities on a 5×5 grid) — nothing like any real task.
  5. Library growth inflates the target's cost across rounds. Uniform-type cost
  per fn node is log|fn|: 1.95 nats at 7 primitives, 2.56 after six invented
  abstractions. Every corner-family abstraction stitch invents makes the
  still-unsolved witness program more expensive unless the abstraction is on
  witness's own path.

  What I'd do, in order of leverage

  1. Put plain wall-belief scaffold tasks in the default corpus (or just run
  with --curriculum). This is the designed fix and the whole ladder follows:
  scaffold solves from scratch → stitch antiunifies wall-derive and step-derive
  forks into the constructor-with-derive-hole → witness drops to ~window 6, dual
  to ~window 6–7. The headline claim is unaffected since scaffold tasks are
  already excluded from the verdict.
  2. Soften the stall-break: only break after a round on the uniform/content Q
  also adds nothing (or require two consecutive stalls). Right now the uniform
  fallback can never run in a stalled run.
  3. Fix the dreamed-Q flooding: renormalize per type after the uniform
  flooring, or use the model only to reorder within a window, or skip the
  dreamed Q for tasks whose family has zero replays (belief) — those are the
  tasks it can only hurt.
  4. If dreaming should ever help witness/dual: make the encoder pool per-mover
  (or value-agnostically per entity) and sample fantasies with two movers + two
  goals matching corpus statistics; the current fantasies and encoding can't
  represent the scenes that need steering.
  5. Optional, for dual's 4 coord latents (6.4 nats of pure latent even with the
  constructor): a coord prior that boosts cells adjacent to trajectory turning
  points — the phantom wall is always next to the detour corner. More
  engineering, only needed if dual is still the long pole after 1–3.

  One caveat worth checking on your next run: if even goal-displacement isn't
  solving (window 6, same depth as plain belief), the blocker is items 3/4
  rather than program depth — that family should solve in round 1 at t_fn=180,
  and its failure would point at the Q/stall dynamics, not at missing
  abstractions.

  Phase 2: same diagnosis, one level deeper — plus one new structural gap

  The decomposition itself is cheaper than it looks. The plumbing types are tiny
  (fn_g_p: 3 symbols, fn_p_p: 4, locate/place: singletons at cost 0), so
  spelling out fork costs only ~+3.6 nats and the sync decomposition is
  essentially free. But that still shifts every family up:

  ┌───────────────────────────┬──────────────────────┬──────────────────────┐
  │          family           │   phase 1 (nats /    │   phase 2 (nats /    │
  │                           │       window)        │       window)        │
  ├───────────────────────────┼──────────────────────┼──────────────────────┤
  │ plain wall belief         │ 13.9 / 6             │ 17.5 / 8             │
  │ (scaffold)                │                      │                      │

  ├───────────────────────────┼──────────────────────┼──────────────────────┤
  │ witness belief            │ 18.5 / 9             │ 22.1 / 11            │
  ├───────────────────────────┼──────────────────────┼──────────────────────┤
  │ dual belief               │ 29.7 / 14            │ 36.9 / 18            │
  └───────────────────────────┴──────────────────────┴──────────────────────┘

  Two consequences:

  1. The scaffold rung itself becomes the gate. In phase 1 plain belief solves
  from scratch at window 6; in phase 2 it sits at window 8 — roughly e^3.6 ≈
  35–50× more search. The first-solve of any fork∧sync compound is now the
  bottleneck, and t_fn=180 that barely suffices in phase 1 almost certainly
  doesn't here. Dual at window 18 is ~e^23 beyond phase-1 plain belief — pure
  enumeration will never touch it; it's reachable only via the agent
  constructor.
  2. The chicken-and-egg now applies to fork itself, and the corpus can't break 
  it. Phase 2's whole point is that fork must be rediscovered as (pipe_gpg 
  (compose_gp dup (mapsnd $f)) $c) with holes at both the derive and the commit.
  Stitch can only anti-unify that skeleton out of solutions where those slots
  vary. But in the current corpus the fork plumbing appears in exactly one
  solved pattern — overlay's (… (mapsnd (step v d))) overlay) — until a belief
  task solves. One pattern means stitch's MDL-optimal move is to bake step and
  overlay into the abstraction (holes cost a token per use and save nothing). So
  the two-hole fork never forms from non-mental evidence, the agent constructor
  never forms without it, and witness/dual stay unreachable — the phase-1
  ladder failure, reproduced one level down. (The sync side is fine:
  registration solutions vary in v, so fn_sync($v) = (register (locate $v) 
  (place $v)) forms with a hole — though it buys nothing at search time, since
  locate/place already cost 0. All the depth is on the fork side.)

  Phase-2-specific aggravators on top of the phase-1 loop pathologies (which all
  carry over — stall-break, dreamed-Q flooding, |fn| inflation):

  - Window density around the target explodes. The complements are deliberately
  same-cost neighbors: 4 choices at every fn_p_p slot
  (mapsnd/swap/mapfst/bimap), 3 at every fn_g_p slot
  (dup/compose_gp/pair_blank). Most well-typed plumbing combinations are
  extensionally degenerate (e.g. pipe_gpg dup fst_gg = identity) but each must
  be enumerated and evaluated. The target's cost rises only 3.6 nats; the time 
  per window rises by the product of those branchings.
  - Dreaming is even less aligned. Fantasies sampled from the phase-2 DSL are
  dominated by degenerate plumbing programs, and the recognition model has to
  predict plumbing tokens that appear in no replay until belief solves — so the
  rounds-2–3 dreamed Q is again strictly worse than uniform for the belief
  families.
  - Commit ties. (sync_except gv) at 2.2 nats now exactly ties (register (locate
  av) (place av)) at 2.2, so expect the degenerate scope-complement commit to
  win the tiebreak at least as often as in phase 1. Not a solve blocker (your
  _belief_commit_form machinery counts it as the agency commit), but the
  constructor stitch invents may be the degenerate form.

  What to do for phase 2

  1. Everything from phase 1 first — scaffold on by default, softened
  stall-break, per-type-renormalized (or gated) dreamed Q. Phase 2 inherits all
  of it via run_phase.
  2. The high-leverage phase-2-specific fix: make fork's slots vary in 
  non-mental solutions. Add one more fn-rooted fork family with a different
  commit — e.g. a ghost/blend variant fork(step v d, underlay), or a fork family
  with a non-step derive. Then anti-unification across non-mental solutions
  alone yields the two-hole fork skeleton before any belief solves. This is not
  a concession — it strengthens the thesis narrative: fork is rediscovered from
  purely non-mental evidence, and belief pays only for the recombination with
  the sync commit. With the fork skeleton + fn_sync + obstacle's policy, plain
  belief drops to ~12 nats (window 5–6); once scaffold beliefs solve and the
  full agent constructor forms, witness lands at ~10.6 (window 5) and dual at
  ~13 (window 6) — the same endgame as phase 1.
  3. Budget the first solve realistically. Round 1's gate is
  goal-displacement/scaffold at windows 7–8; give round 1 a larger --t-fn (this
  is what your per-task timing printout was built to calibrate) rather than
  raising it uniformly across rounds.
  4. Optionally, add a --probe mode that prints exactly this table (GT cost
  under the live Q, per family, per round) from the running experiment — it
  turns "belief didn't solve" into "belief is N windows past what the timeout
  bought," which is the number every one of these decisions hangs on.

❯ what kinds of tasks shoud I add for phase2? should any tasks be added for     
  phase1?                                                                       
⏺ Short answer: yes to both — and the design rule for choosing them is the same
  in each case. Stitch keeps a slot as a hole only if solved programs vary at
  that slot; it bakes anything constant. So work backwards from the constructor
  you need, list its slots, and make sure each slot is varied by at least two
  families that are solvable from scratch. A task family earns its place if it
  (a) solves in window ≤6 from raw primitives, and (b) makes some slot of the
  target constructor vary across the stitch pool.

  Phase 1 additions

  1. Plain wall-belief scaffold — on by default (window 6). Already written
  (--curriculum); it just needs to stop being opt-in. This is the only fork∧sync
  compound reachable from scratch, and without it nothing else below matters.

  2. Nothing new needed for the derive hole — scaffold + goal-displacement 
  already do it. This is worth noticing: anti-unifying scaffold solutions (fork 
  (compose (wall_at r c) seek) (sync av)) with goal-displacement solutions (fork
  (compose (step gv d) seek) (sync av)) differs exactly at the derive subtree,
  so stitch's optimal shared abstraction is fn_agent($f, $gv, $av) = (fork 
  (compose $f (optimize (neg_dist $gv) $av)) (sync_to_world $av)) — the agent
  constructor with the derive hole and the shared-av agency signature. Your two
  existing belief variants are the derive-diversity mechanism; they just both
  need to be in the solvable pool at once.

  3. A two-agent non-mental family (window ~3): (compose (optimize (neg_dist 
  gv1) av1) (optimize (neg_dist gv2) av2)). Two true-belief seekers, no walls,
  no fork. This buys two things witness/dual currently lack:
  - The outer wrapper compose(·, seek) recurs non-mentally. Together with a
  variant where the first component is physics (compose (step v d) (optimize …)
  — an object falls while an agent seeks), the first slot varies, so stitch can
  form fn_scene($f, $gw, $aw) = (compose $f (optimize (neg_dist $gw) $aw)).
  Witness belief then = fn_scene(fn_agent(...), gw, aw) ≈ 8 nats — window 4.
  - It's the only way the recognition model ever sees 4-entity, two-mover
  replays. Right now every dreamed replay has one mover, so the encoder's
  role-by-motion pooling is guaranteed to misread witness/dual scenes.

  4. Optionally: real-wall obstacle scenes with a second agent. Non-mental (the
  wall is rendered), 4 entities + wall. Pure recognition-model diet plus making
  wall_at + seek + seek co-occur non-mentally. Lower priority than 1–3.

  One balance note: you'll have ~96 deep belief tasks vs a handful of donors.
  Stitch compresses where the corpus mass is, but solved-program mass is what
  counts — early rounds it's all donors, which is what you want. Just keep the
  scaffold family big enough (≥2 per combo) that the constructor's holes are
  supported across combos, or B′ will show per-combo specializations.

  Phase 2 additions

  Everything above carries over (same run_phase corpus). The phase-2-specific
  target is the two-hole fork skeleton (pipe_gpg (compose_gp dup (mapsnd $f)) 
  $c), which currently can't form because overlay is the plumbing's only
  non-mental user and pins both slots. So vary each slot:

  1. Vary the commit: a fork+underlay family (world-wins motion trail). GT (fork
  (step v d) underlay). Extensionally distinct from overlay only when the mover
  crosses another object (overlay lets the model copy overwrite the world;
  underlay preserves it), so generate scenes with an occluding bystander and
  reject any scene overlay-commit also explains — same rejection pattern as your
  existing _physically_explainable filters. Decomposed cost ≈ 11 nats, window
  5.

  2. Vary the derive: fork+overlay with a seek-derive (comet trail). GT (fork 
  (optimize (neg_dist gv) av) overlay) — a goal-seeker leaving a trail. Same
  commit as the existing overlay family, different derive. Window ~5 decomposed.

  With 1 + 2 + the existing overlay family, the stitch pool contains
  fork-plumbing solutions at three (derive, commit) combinations — (step, 
  overlay), (step, underlay), (seek, overlay) — and the MDL-optimal shared
  abstraction is the two-hole skeleton, i.e. fork gets rediscovered from purely 
  non-mental evidence. That's a stronger version of your thesis claim, not a
  concession: belief then pays only for recombining the rediscovered fork with
  the registration-donated sync.

  3. What I would not add: families for pair_blank, mapfst, bimap, swap. With
  the current fn primitives, pair_blank compounds are extensionally degenerate
  (deriving from a blank grid collapses to the derive itself), and mapfst/bimap
  trail variants are near-indistinguishable from the dup/mapsnd ones on
  mostly-empty grids — you'd be generating scenes whose uniqueness filters are
  more fragile than the claim they support. They're already in your no_home set;
  leave them as live-but-unclaimed corners and say so in the write-up.

  Expected ladder after these: phase-2 round 1 solves donors (windows 3–5) and
  goal-displacement (7, the long pole — calibrate round-1 t_fn to it); stitch
  forms the fork skeleton + fn_sync + policy; scaffold belief drops to ~window
  5–6 and solves; stitch forms fn_agent; witness (~window 5 via fn_scene) and
  dual (~window 6) follow. No rung deeper than window 7 anywhere, versus window
  11 and 18 today.
