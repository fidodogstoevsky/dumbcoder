⏺ Phase 3 (phase3_arity.py + the gstack section of dsl.py + make_stack_prims in
  prims.py) closes the last stipulation left open by the cube: phases 1/2 show
  belief's role structure is discovered, but every cube combinator is hardwired
  to arity 2 (pair_gg), so "why one world + one model, not three?" was still
  answered by the interpreter's type, not by search. Phase 3 makes channel count
  the free parameter.

  How it works

  The calculus. The fixed pair is replaced by one recursive type, gstack ::= () 
  | (grid, *gstack), with depth-polymorphic combinators that are each the n-ary
  lift of a cube op (dsl.py:601-683): base lifts the world to a 1-stack,
  dup_top/blank_top push (the dup/pair_blank corners), map_top runs a policy on
  the head only (mapsnd/on_model), swap_top exchanges the top two, zip_top
  combines the top two with a pair-consumer like overlay (popping one),
  commit_top is the n-ary sync_to_world (read v off the top, impose on the world
  below, pop), and peek renders. compose_gs/pipe_gsg are the n-ary
  compose/pipe. The anchor identity fork_stack_decomposed(derive, av) ≡ 
  fork(derive, sync_to_world(av)) proves depth-1 reproduces the atomic calculus
  exactly, and it's asserted in verify_ground_truth.

  The DSL (make_stack_prims) is deliberately the lean atomic core plus the stack
  — not the cube — because role and arity are orthogonal axes, and the atomic
  fork/sync stay in so the searcher genuinely chooses depth rather than being
  forced into the stack.

  The corpus is physics, desire, overlay, belief, plus the new crossblur family:
  w ∪ shift_d1(w) ∪ shift_d2(w) iterated, generated through a height-3 stack
  program (crossblur_prog) and filtered by _low_arity_explainable so it's at
  least a genuine two-direction effect. Crucially it is not required to need
  arity 2 — being a union it serializes, and the searcher is expected to solve
  it at arity 1. Its job is to be the expressibility witness: the hand-built
  height-3 ground-truth program runs, proving the calculus can hold a third
  grid.

  The run is standard wake-sleep ECD (like phases 1/2 but with a custom worker
  _solve_task_md because stack programs need maxdepth=14, deeper than ecd's
  hardcoded 10): enumerate under a content-prior Q → joint stitch over all
  solutions (abstractions registered into D for the next round) → dream a
  recognition Q on replays + fantasies → repeat.

  The verdict machinery. _arity(sol) = max grids held simultaneously − 1: for
  stack programs it token-scans the left-nested compose_gs spine counting pushes
  (dup_top, blank_top) and pops (commit_top, zip_top) to get peak height; for
  atomic programs it's 1 if fork appears, else 0. The census then checks the A″
  pattern: physics/desire select 0, belief selects exactly 1, crossblur
  serializes back to 1, max selected = 1 while max expressible ≥ 2. Conclusion:
  belief's single private model is the generic minimal-sufficient arity (shared
  with non-mental overlay/crossblur), so what makes belief belief is the commit
  direction (the cube axis), not the channel count. Part (B) additionally checks
  the joint stitch still extracts the agent constructor with the shared-$0
  (actor-and-committer) signature.

  How it could be improved

  Roughly in order of how much they'd strengthen the thesis argument:

  1. Separate MDL preference from search failure — this is the big one. "MDL
  never selects arity 2" is currently indistinguishable from "the enumerator
  never reaches depth-2 stack programs within the timeout." The expressibility
  witness is hand-written, not found; no task in the corpus is ever solved
  through the stack at all (belief goes through atomic fork, crossblur
  serializes). Two cheap fixes: (a) an ablation run with atomic
  fork/sync_to_world removed from the DSL, so belief is only solvable via the
  depth-1 stack path and crossblur only via depth-2 — if the searcher finds
  those, you've shown stack programs are reachable, and the joint run's arity-1
  choice becomes a genuine preference; (b) report the MDL costs directly: for a
  crossblur task, compute the description length of the found arity-1 program
  and the ground-truth arity-2 program under the final library and print the
  margin. That turns "never selected" into a quantified analytic claim rather
  than an absence of evidence.
  2. Compute arity semantically, not by token scan. The scan in _arity
  (phase3_arity.py:247) assumes textual order = application order and that base
  starts the one and only stack. Both assumptions break on nested stacks:
  map_top takes an fn, and pipe_gsg(...) is an fn, so a stack program can appear
  inside map_top — the inner base then resets h = 1 and corrupts the outer
  count. normalize does inline invented abstractions (dsl.py:1006), so that gap
  is covered, but the robust fix is instrumentation: run the solution on a probe
  grid with the stack combinators wrapped to record peak len(s). That's the
  honest measurement and it's ~15 lines.
  3. The "uniform mop-up" comment overpromises. The code comment says a uniform
  round after DREAM_USE_ROUNDS keeps search complete, but with the default
  rounds=3 and use_model = it <= 1 + DREAM_USE_ROUNDS (= 3), every post-dream
  round uses the model — no mop-up ever runs in the full configuration. Either
  set rounds=4 or shrink the window; as-is, a mis-prioritizing Q model actually
  can make a deep program unreachable, which is exactly the failure mode the
  comment claims is excluded (and it interacts with point 1).
  4. A single seed and ~20 tasks is thin support for a "never" claim. The
  verdict quantifies over 4–6 tasks per family at seed ∈ {0,1,2,3,5} fixed. A
  small multi-seed sweep (even 3 seeds × the census only) would let you say "in
  N runs, arity >1 was selected 0 times" — much better footing for the thesis
  chapter.
  5. Acknowledge (or fix) that depth ≥ 3 is only weakly accessible. swap_top
  only exchanges the top two, so a third channel can only be reached after a
  pop. Arity ≥ 3 is expressible but the combinator set is biased against it,
  which slightly softens "free parameter." Either add a rot_top and show the
  census is unchanged, or add a sentence in the writeup owning the asymmetry —
  the claim only needs arity 2 vs 1, so owning it is probably fine.
  6. Smaller things. commit_top hardwires the commit direction (sync_to_world),
  so the stack is not direction-symmetric — fine for phase 3's scope, but the
  natural "future work" is the cube × stack product where both axes are
  simultaneously free. And _solve_task_md pickles D and a fresh Q tensor into
  every task's args; shipping D once via initargs would cut per-task overhead in
  the full run.

  The core design is sound — the serialization finding (arity = simultaneous
  grids, unions fold) and the resulting analytical A″ verdict are the
  intellectually honest version of the claim. The main exposure is #1: right now
  the stack is expressible-but-unexercised, and a skeptical reader will ask
  whether the searcher could ever have chosen it.

❯ is the gstack machinery sufficient for the argument? is a fully polymorphic   
  DSL with arrow types not necessary?                                           

⏺ Short answer: yes — for the claim phase 3 actually makes, the gstack is
  sufficient, and full polymorphism would not only be unnecessary but would
  actively damage the experiment. But it's worth being precise about why,
  because the gstack does still stipulate things, and the thesis should say so
  explicitly rather than let a reader discover it.

  What the argument needs, and what gstack provides

  The claim is comparative: with arity ≥ 2 expressible at honest marginal cost, 
  joint MDL selects arity ≤ 1. That requires exactly three properties of the
  hypothesis space:

  1. Unbounded expressibility — programs holding n grids simultaneously exist
  for every n. The recursive type gives this; the height-3 witness runs.
  2. Fair costs at the margin — arity n+1 must cost only O(1) tokens more than
  arity n (one push, one consume), so a preference for arity 1 can't be an
  artifact of a rigged price. The stack has this: crossblur at arity 2 is
  dup_top … zip_top more than at arity 1, not some exponentially awkward
  encoding.
  3. A well-defined census — "number of private channels" must be measurable on
  found solutions. Peak stack height gives this.

  Property 3 is the underappreciated one, and it's where the polymorphic
  alternative actively fails. In a language with real arrow types and lambda
  abstraction, a program can smuggle channels through closures: λw. 
  combine(f(w), g(captured)) holds a grid in an environment, invisible to any
  syntactic census. "Grids held simultaneously" stops being a property of the
  program and becomes a property of the evaluator's environment at runtime —
  you'd have to instrument the heap to measure arity at all, and the clean
  statement "belief selects arity 1" would dissolve into an operational claim
  about a particular evaluation strategy. The gstack reifies channels as stack
  cells precisely so that arity is legible. That's not a shortcut; it's what
  makes the dependent variable exist.

  There's also the experimental-design point: full polymorphism blows up typed
  enumeration (type-variable instantiation, unification during search) exactly
  where phase 3 is already weakest — the search-failure-vs-MDL-preference
  confound we discussed. At maxdepth=14 the monomorphic search is already at the
  edge; in a polymorphic space, "never selected arity 2" would be
  uninterpretable, because nothing deep would be reachable at all. The gstack is
  the minimal intervention that frees the one variable under study while
  holding search burden roughly fixed — that's better methodology than maximal
  generality, not a compromise of it.

  What gstack still stipulates — and whether it threatens the claim

  Honesty requires listing the residual interpreter commitments:

  - Homogeneous grid channels (no heterogeneous state),
  - LIFO access discipline (swap_top reaches only the top two; deeper channels
  are reachable only via pops),
  - The particular basis (each op is the n-ary lift of a cube op).

  Do these bias the verdict? The threat would be a bias against arity 2 making
  "not selected" an artifact. But arity 2 needs only the top two cells, which
  the discipline fully supports at fair cost — the LIFO awkwardness only bites
  at arity ≥ 3, and the thesis claim only needs 2 vs 1. The basis choice is
  defensible on symmetry grounds: it's not an ad hoc gadget set but the closure
  of the existing calculus under "make it n-ary," which is the same move the
  cube made for roles. I'd state this in the chapter as: the type went from 
  "arity fixed at 2" (pair_gg) to "arity unbounded" (gstack); what remains fixed
  is that channels form a sequence, not their number — and the number was the
  question.

  The deeper reason the verdict survives basis-dependence is the serialization
  finding, which is calculus-independent: union-style combines fold, so the
  arity-1 program exists and is shorter in any language that has composition —
  including a fully polymorphic one. A richer language can only flip the verdict
  by containing a task-relevant non-serializable ternary combine, and no such
  task is in the corpus (or, arguably, in the natural task distribution at all).
  That's why the A″ verdict is analytical rather than merely empirical, and
  it's the right thing to lean on when a committee member asks exactly your
  question.

  What polymorphism would buy — a different, stronger claim

  A fully polymorphic DSL would let dup_top/swap_top/zip_top be derived from
  generic pair/fold combinators rather than provided — i.e., it would show the
  channel machinery is discovered, not just the channel count. That's the
  [[synthesis-not-primitive]] principle pushed one level up, and it's a
  genuinely stronger result. But it's a different thesis, it inherits the
  closure-opacity and search-explosion problems above, and phase 3's claim
  doesn't need it. It belongs in future work, framed as: "we freed the count;
  freeing the calculus itself requires solving arity-legibility under
  higher-order abstraction."

  Two cheap moves for the writeup

  1. State the serialization lemma explicitly as the basis-independence
  argument: "any calculus with sequential composition admits an arity-1 solution
  to fold-style combines that is no longer than the arity-2 one; hence the
  verdict is not an artifact of the stack discipline."
  2. A basis-perturbation check: add rot_top (or an indexed peek) to the DSL,
  rerun the census, show it's unchanged. One combinator, one run, and it
  empirically demonstrates the verdict doesn't hinge on the particular access
  discipline — the cheapest possible answer to "isn't the stack itself a
  stipulation?"

  So: gstack is sufficient for the count claim, provided the chapter (a) names
  the residual stipulations, (b) argues fairness-at-the-margin for 2-vs-1, and
  (c) carries the serialization lemma as the reason the result generalizes
  beyond this basis. Arrow-type polymorphism is the answer to a question phase 3
  isn't asking — and it would make the question phase 3 is asking unmeasurable.
