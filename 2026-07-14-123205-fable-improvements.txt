  Errors and code issues

  1. Latent silent misalignment between solutions and rewritten programs (the 
  one real bug). saturate_stitch drops any rewritten program that fails to parse
  (ecd.py:565-579 builds new_trees only from successes), but both callers pair
  the results positionally: dict(zip(sol_keys, rewritten_strs)) at ecd.py:910
  and experiment.py:933. One parse failure shifts every subsequent key onto the
  wrong program — corrupting the usage census (A), the constructor-specificity
  check (B), the run artifact, and therefore the MDL margins, with no error
  raised. I checked your actual runs: phase1_run.json (200/200) and
  phase2_run.json (186/186) are fully aligned and the logs contain zero "could
  not parse rewritten" lines, so nothing published is affected — but the code
  path for parse failures exists and even has a fallback (training_trees reverts
  when >half fail), so it's expected to fire eventually. Fix: return one entry
  per input (None on failure), or return a dict keyed by the input string.

  2. make_false_obstacle_belief_tasks is written but never used. This family
  (tasks_minds.py:759) was engineered precisely to kill the scope-complement
  degeneracy — the awkward disclosure in verdict (A) where belief solutions
  commit via sync_except gv/sync_all and you argue extensional equivalence. It's
  imported by nothing; run_phase and mdl_margin.build_corpus don't include it.
  Wiring it in would let the verdict say "the literal sync_to_world(av) commit
  was forced and found," instead of "the degenerate commit counts as agency by
  argument." This is the cheapest, highest-leverage strengthening available in
  the repo.

  3. The behavioural-competitor test compares agent positions, not frames.
  _reproduces_behaviour (mdl_margin.py:119) checks only the observed agents'
  trajectories. A rival that matches the agents but renders the goal or wall
  differently is counted a "competitor" when it actually renders a different
  scene — and for belief_goal the stationary goal is the discriminating witness,
  yet it isn't in _observed_agents. The error direction is conservative for the
  margin claim, but it can spuriously trigger the "genuine shorter competitor"
  warning. Full-frame equality (np.array_equal(xr, x)) is both stricter and
  simpler; keep the agents-only check as a secondary label if you want to
  distinguish "wrong scene" from "wrong action."

  4. Smaller items, roughly in priority order:
  - _remap_names (mdl_margin.py:226) applies substitutions sequentially; if the

  Strengthening the "discovered, not stipulated" argument

  Lesion controls (turn "discovered" into a causal claim). You show the
  constructor emerges from the mixed corpus; you don't show it wouldn't emerge
  otherwise. Two cheap ablations: (a) run the identical pipeline with the belief
  families removed and show no fork∧sync∧shared-av abstraction is invented —
  the constructor is driven by the evidence, not by the primitive inventory; (b)
  run with the non-mental fork/sync donors (overlay/comet/registration) removed
  and show belief becomes unreachable or the constructor doesn't generalize —
  the parts genuinely earn their keep. Both reuse run_phase with a corpus flag.

  Held-out transfer. All current evidence is within-corpus, and the corpus was
  visibly tuned (the n_obstacle = 6 comment admits obstacle got ~3× mass so the
  wall policy survives stitch — a skeptic will call that curation). The standard
  DreamCoder-style answer: hold out belief tasks (unseen (av,gv) combos,
  ideally a larger grid), and show the learned library solves them in seconds
  where the base DSL times out, with the constructor in the solution. That
  converts "the verdict passed on the corpus we built" into "the abstraction
  generalizes."

  Certified minimality instead of a rival battery. mdl_margin argues "every
  rival we thought of is longer." But your enumeration is already cheapest-first
  under Q — the found program is, by construction, the cheapest program (within
  a LOGPGAP window, per root type) that reproduces the scene. You can state
  that as a theorem-shaped claim, and/or run exhaustive enumeration under the
  final library up to DL(found) and report that no shorter program reproduces
  the trajectory. That upgrades the margin figure from "the skeptic's candidates
  lose" to "no shorter description exists up to budget," which is the actual
  MDL claim.

  Report the no-dream verdict as the headline. MatRecognitionModel identifies
  mover/goal/wall roles by motion — that's proto-agency structure baked into the
  neural guide. The uniform floor in dreamed_q correctly guarantees the model
  can't make anything reachable that wasn't, but for the discovery claim the
  clean presentation is: the verdict holds under --no-dream (uniform/content
  prior only), and dreaming is purely a wall-clock optimization. If you don't
  have a full no-dream run at full timeouts, that's worth producing for the
  thesis.

  Prior robustness for the margins. DL in nats under uniform_type_q depends on
  the type partition and on library size — adding cube corners changes every
  symbol's cost, so a margin of +8 nats is partly an artifact of the pricing
  convention. Report the margins under two or three conventions
  (type-conditioned uniform, flat per-symbol, raw node count) and show the sign
  never flips. One paragraph, kills a whole referee objection.

  Seed robustness. Every family is generated from a single fixed seed and the
  headline is one run. Even 3–5 corpus seeds with "constructor invented: 5/5,
  margin median across runs" would move the claim from anecdote to result.

  Show the shared-hole mechanism isn't rigged. The agency signature is "one hole
  bound in both derive and commit." It would strengthen the story to show
  stitch invents shared-hole abstractions elsewhere when the evidence warrants
  (so the mechanism is generic), while the specific fork∧sync∧shared-av
  combination arises only for belief. A matched non-mental family whose ground
  truth is an equally deep compound with a repeated variable would be the clean
  control.

  Generalizations

  Persistent belief state (the big one). Right now the private model is
  rederived inside fork every frame — belief content (the wall coordinate) is a
  free latent the searcher fills per task, not a state the agent acquired. That
  means the current construct is really "per-frame counterfactual stamping," and
  a critic can say the intensional state is posited, not represented. The
  natural next phase: tasks where the false content comes from the agent's own
  observational history — object seen at A, moved to B while unobserved, agent
  goes to A. That's literally Sally-Anne, and it's inexpressible without a model
  that persists across frames. You could get there in program space (keeping
  the interpreter single-grid in spirit) with a fold-with-carry combinator over
  the stack calculus, letting sync_to_model (your perception corner!) write the
  model and the agency commit read it. This would unify the direction axis —
  perception and action become the two dataflow directions through one
  persistent channel — and eliminate the latent-coordinate objection, because
  the belief content would be derived from the trajectory rather than
  enumerated.

  Second-order belief. fork nests: a derive can contain another agent's fork.
  dual_belief has two first-order beliefs; a genuine second-order task (A acts
  on its model of B's model — e.g., A intercepts where it predicts the deceived
  B will go) would test whether the discovered constructor composes with itself,
  which is exactly the recursion that makes intensionality interesting. If
  stitch reuses the same constructor at both levels, that's a striking result.

  Decompose desire too. optimize(neg_dist gv, av) is a quasi-primitive
  utility-maximizer, so "desire" is currently stipulated in a way belief is not.
  Decomposing it (a value function + an argmax-step combinator, each with
  non-mental uses) would let you claim the whole belief–desire pair is
  discovered, not just belief — a full discovered BDI core.

  A second substrate. "Domain-general foundations" is currently demonstrated
  within one domain. Porting the pipeline to a structurally different substrate
  (1-D tapes or string rewriting, with analogous seek/obstacle/false-belief
  tasks) and showing the same product-category combinators plus the same
  shared-variable signature emerge would demonstrate domain-generality rather
  than assert it. fork/dup/mapsnd/register are already substrate-agnostic in
  spirit; only the grid core would need replacing.

  Arity over minds, not just channels. Phase 3 shows channel count is
  discovered; the parallel question is agent count. Dual belief hints at it —
  does the library learn "one constructor application per agent-value," making
  the number of minds in a scene a discovered structural feature the same way
  channel arity is?
